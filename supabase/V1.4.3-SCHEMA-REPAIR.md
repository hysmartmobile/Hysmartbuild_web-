# HySmart Build v1.4.3 — schema repair

The API v1.4.3 reads `companies.billing_country_code`, `tax_country_code`, and `unit_system`.
If `/api/v1/me` reports `column companies_1.billing_country_code does not exist`, the
database has not received the company billing identity columns.

Apply:

```bash
supabase db push
```

or run the migration:

`supabase/migrations/20261003090000_v1_4_3_company_identity_schema_repair.sql`

After applying it, restart the API:

```bash
npm run dev
```

This migration is idempotent and does not delete company data. It backfills billing/tax
country from `country_code` for existing companies and defaults `unit_system` to `METRIC`.

The full `20261002180000_v1_4_3_global_billing_identity.sql` migration should also be
applied if the database has not yet received the other v1.4.3 billing tables and pricing
configuration.
